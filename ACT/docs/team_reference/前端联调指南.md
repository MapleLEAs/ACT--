ATC 监控系统 前端联调指南
一、后端框架整体说明
核心框架：Django 4.1.5 + Django REST Framework (DRF) 3.14.0
接口前缀：
业务接口：/api/（如 /api/devices/、/api/alarms/、/api/status-logs/）
NGSI-LD 接口：/api/ngsi/（如 /api/ngsi/devices/{device_id}、/api/ngsi/alarms/）
数据库：MySQL（生产）/ SQLite（开发）
部署方式：WSGI 容器（Gunicorn + Nginx），支持容器化部署
核心能力：
设备 / 告警 / 状态日志的标准化 REST API
告警 ACK/CLEAR 操作与统计
NGSI-LD 格式输出，支持跨系统数据共享
二、鉴权约定
开发环境：免鉴权，可直接访问所有接口，便于联调。
生产环境（预留）：采用 JWT 鉴权，前端需在请求头携带：
http
Authorization: Bearer <jwt-token>
登录接口（预留）：
POST /api/auth/login/：用户名 / 密码换取 Token
POST /api/auth/refresh/：刷新 Token
三、CORS 配置
开发环境：后端已配置 CORS_ALLOW_ALL_ORIGINS = True，前端无需额外配置即可跨域访问。
生产环境：将配置为指定前端域名，如：
python
运行
CORS_ALLOWED_ORIGINS = [
    "http://localhost:8081",
    "https://atc.example.com"
]
四、状态码与错误处理
状态码	含义	前端处理建议
200 OK	操作成功（GET/PUT/PATCH）	展示成功提示，更新页面数据
201 Created	资源创建成功（POST）	跳转至详情页或刷新列表
204 No Content	资源删除成功（DELETE）	刷新列表，无额外提示
400 Bad Request	请求参数错误	解析 detail 字段，在对应输入框展示错误
401 Unauthorized	未认证 / Token 无效	跳转登录页，清除本地 Token
403 Forbidden	权限不足	提示 “无权限操作”，禁止重试
404 Not Found	资源不存在	展示 “资源不存在”，返回上一页
500 Internal Server Error	服务器内部错误	展示 “服务暂不可用”，提供 “点击重试” 按钮
错误响应格式示例：
json
{
  "error": "参数错误",
  "detail": "device_id 为必填字段",
  "errors": {
    "device_id": ["该字段不能为空"]
  }
}
五、前端页面具体实现建议
1. 设备管理页
列表页：
接口：GET /api/devices/
过滤：支持按 status（online/offline/error）过滤，按 name/device_id 搜索
分页：每页 20 条，支持页码切换
操作：编辑、删除、状态变更（调用 /api/devices/<id>/change-status/）
详情页：
接口：GET /api/devices/<id>/
关联展示：
状态日志：/api/status-logs/?device__device_id=<device_id>
告警：/api/alarms/?device__device_id=<device_id>
2. 告警管理页
列表页：
接口：GET /api/alarms/
过滤：按 status（ACTIVE/ACK/CLEARED）、level（CRITICAL/WARNING/INFO）、device__device_id 过滤
批量操作：ACK/CLEAR（调用 /api/alarms/<id>/operate/）
统计卡片：GET /api/alarms/stats/ 展示各状态 / 级别告警数量
详情页：
展示告警级别、状态、触发时间、关联设备信息
支持手动 ACK/CLEAR，操作后刷新状态
3. NGSI-LD 数据展示页
接口：GET /api/ngsi/devices/、GET /api/ngsi/alarms/
响应格式：application/ld+json，包含 @context、id、type 等标准字段
前端可按需解析实体属性，按 NGSI-LD 规范渲染
